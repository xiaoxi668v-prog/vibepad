# Orbit · 安卓 Pad 控制电脑 · UI 实施说明

版本：2026-09-10 / 02、05 入选版。以包内可交互 HTML、PNG 截图和实测尺寸为准。两套设计沿用同一组功能与交互逻辑，仅改变布局和视觉变量。

## 1. 保留的设计

| | 02 深空专业 | 05 双手操控 |
|---|---|---|
| 视觉 | 深空灰底、分层深色面板、灰蓝主按钮 | 温暖钛色、柔和面板、浅浮雕按键、棕色主按钮 |
| 布局 | 上方 Touch Bar；左侧大触控区；右侧快捷键；底部 App Dock | 上方 Touch Bar；左侧 App 与编辑键；中央触控区；右侧快捷键与语音 |
| 主要使用方式 | Pad 放在桌面，右手操作快捷键 | 双手持握或支撑 Pad，两侧拇指分担操作 |
| 区分方式 | 触控面板面积、深色层次、主按钮强调 | 中央触控、左右分工、可感知的键帽层次 |

保留原编号 02、05。不要将 05 改称方案 02，以免与前一轮评审混淆。不要把两套界面的局部元素混合成第三套方案。

## 2. 画布与布局

独立界面文件在 **1280 × 800 CSS px** 横屏画布下导出。该尺寸是设计参考，不是指定安卓设备的物理像素分辨率。移植时应根据设备密度、窗口尺寸和实际可触达范围确定 dp / sp，不能直接把截图像素当作 dp。

包内独立界面没有外围设备圆角和投影；这些装饰只出现在双方案比较预览中。正式 App 不需要实现比较页的标题、编号、选择器、演示说明，也不需要模拟平板外壳。

### 02 深空专业

- 状态栏高 70；水平边距 24。品牌和 Coding / 日常模式在左，电脑连接、时间、电量与设置在右。
- 工作区左右与底部留白 18；主要分区间距 13。
- 网格列：`minmax(0, 1fr) 316px`。右栏固定参考宽度，剩余宽度留给触控区。
- 工作区行：Touch Bar 60；中间区域占剩余高度；底部 App Dock 84。
- 右侧快捷键面板内边距为上下 20、左右 17；5 列，列间距 8。1280 参考画布下单列键宽约 50，高 68。
- 语音按钮放在右栏底部；高度 60，与发送键同排。
- 底部 App Dock 展示 9 个 App，图标 32 × 32，名称保留，当前 App 使用灰蓝浅底强调。

### 05 双手操控

- 状态栏高 71；左右边距 24。
- 工作区左右边距 17、底部 20；分区间距 14。
- 网格列：`220px minmax(0, 1fr) 220px`。中心触控区占剩余宽度。
- 工作区行：Touch Bar 60；主体占剩余高度。
- 左右面板内边距为上下 17、左右 13。
- 左侧 App 为 3 列；下方编辑与修饰键为 2 列，间距 7，编辑键高 48。
- 右侧按键为 3 列，间距 7，高 65。中部方向键形成上 / 左下右的空间对应。
- 语音按钮与发送按钮竖排，宽度充满右侧面板，高度分别为 55 与 47。

`measurements.json` 提供最终页面实测的 x、y、宽、高，应以它核对上述布局描述。

### 窗口变化

- 优先支持横屏平板。控制区保持稳定的可点击尺寸；增加的宽度分配给触控区。
- 736 / 1024 宽的预览用于验证收缩时的布局；不意味着建议把平板界面缩成手机操作密度。
- 小于 620 宽时，交付预览纵向排列功能区，方便手机审阅。这个窄屏布局是评审兼容，不是新增的手机产品需求。
- 接入 Android 时，为小图标按钮扩展独立命中区域。项目建议主要操作命中区域至少 48 × 48 dp；保证扩展区域不会互相重叠。调整密度后仍需在目标 Pad 上实际验证。

## 4. 组件与区域映射

| 组件 | CSS / 源码入口 | 数据或事件 |
|---|---|---|
| 顶部状态栏 | `.systembar` / `header()` | 电脑名称、连接、延迟、电量、时间、设置 |
| 常用 App | `.apps-panel` / `appsPanel()` | App 列表、前台 App、切换成功 / 失败 |
| 快捷键 | `.commands-panel` / `commandsPanel()` | 当前模式、按键配置、键盘动作 |
| 触控板 | `.trackpad` / `pad()`、`bindPad()` | 相对移动、多点手势、状态反馈 |
| Touch Bar | `.touchbar` / `touchbar()` | 前台 App 上下文、动作、系统音量与亮度 |
| 语音与发送 | `.voicebar` / `bindVoice()` | 开始、取消、结束、转写、文字发送 |
| 设置面板 | `.modal-layer` / `settings()` | 指针速度、自然滚动、触感、亮度 |

建议将主题变量和布局选择分开：02 与 05 的颜色不同，信息架构也不同，不能只换一份色表就得到另一套布局。

## 5. 交互规定

### 应用切换与 Touch Bar

1. 轻点 App 发出切换意图。原型立即切换选中态；正式版本以 Mac 返回的实际前台 App 为准。
2. 当前 App 保留浅色选中底与小状态点，不仅依赖图标颜色。
3. Touch Bar 随上下文变化：Cursor 显示新建对话 / 终端 / 运行；Chrome 显示后退 / 前进 / 刷新 / 地址输入 / 收藏；QQ 音乐显示媒体控制；Finder 显示文件操作；腾讯会议显示会议控制。
4. 这些是 UI 参考内容。若现有接入返回的是原生 Touch Bar 图片、远端布局或其他数据格式，应保留原协议和真实布局；不要把原型的固定标签误当作 Mac 原生 Touch Bar API 定义。
5. 音量、亮度变化先在 UI 提供即时反馈，再依据远端回执纠正；失败时恢复实际值并显示原因。

### 快捷键

- 短按提供 120–180 ms 视觉反馈；按下时缩放至 0.97 并下移 1，松开恢复。
- Esc、停止、确认 Y、拒绝 N、方向键、空格、剪切、复制、粘贴、删除均保留。
- 05 的 Command 和 Shift 为显式锁定开关，再次点按松开。真实实现必须成对发送按下 / 释放事件，在失焦、断连和取消时释放。
- 交付原型仅示意修饰键组合文字，不发送真实组合键。长按重复、系统快捷键拦截和键位布局应复用现有 App 行为。
- Coding / 日常切换改变快捷键集合，不应改变 App 前台窗口。

### 触控

- 单指拖动：相对移动指针。
- 单指轻点：单击。原型以小于 7 px 位移且小于 450 ms 作为演示判断。
- 双指移动：滚动；双指轻点：右键。
- 三指水平移动：切换工作空间。
- 以上原型阈值只是演示实现，不是生产手势识别器的定稿。多点指针增减、手势取消、双指转单指、三指切换阈值、抬起顺序，需使用现有原生识别逻辑验证。
- 触控中央标题与手势提示降低对比；触摸时退到 30% 不透明度；松开恢复。
- 底部按钮分别打开文字输入、手势指南和沉浸触控。沉浸触控隐藏 App 与快捷键，只保留状态栏、Touch Bar 和触控区域；同一位置可以退出。

### 语音和发送

| 状态 | 视觉与行为 |
|---|---|
| 待输入 | 显示「按住说话」和麦克风 |
| 按住录音 | 按钮变为 `#B95D68`，文字「松开结束」，图标为波形 |
| 取消 | 停止录音，不提交转写；回到初始状态 |
| 转写完成 | 在当前输入状态中准备文字，提供「等待发送」反馈 |
| 点击发送 | 有草稿时发送文字；无草稿时为回车 |
| 长按发送 | 600 ms 后换行；该次松开不能再发送文字 |

Web 原型用固定演示转写，不请求麦克风。文字输入按钮可以打开真实可编辑的本地文本框。生产版本需接入现有录音权限、转写服务和目标输入框，且必须区分用户取消、识别中、识别失败、空转写和发送失败。

### 弹层与反馈

- 弹层背景遮罩 `#11182732`，参考模糊 8，面板宽 390、圆角 24、内边距 23。
- 弹层打开后，底层 UI 不可操作；关闭按钮、Escape 和遮罩空白处均可关闭。关闭后焦点回到原入口。
- 设置更改即时反映在原型状态中；正式版本决定持久化位置并与真实设备值同步。
- 提示条显示约 1.8 s，用于轻量动作反馈，不要用提示条代替连接失败或转写失败等需要处理的持久状态。

## 6. 真实数据接入

| 原型字段 / 操作 | 正式 App 数据来源或处理 |
|---|---|
| 小西的 MacBook Pro、6 ms、09:41、86% | 真实设备名称、连接测量、系统时钟和平板电量 |
| App 名称与前台选中项 | 电脑端 App 列表、图标与前台事件 |
| `updateApp()` | 发送 App 切换意图，等待实际前台状态 |
| `executeKey()` | 映射现有键盘发送协议与回执 |
| `bindPad()` | 映射原生触摸识别器与相对指针协议 |
| `bindVoice()` | 映射录音 / 转写 / 取消 / 发送状态机 |
| 音量、亮度、播放按钮 | 发送远端意图并回显真实状态 |
| 设置中的触感开关 | 使用设备支持的触觉能力 |

UI 演示源码与后端通信保持分离。不要将固定的「成功」反馈直接用作生产端的连接或发送成功判定。

## 7. 生产状态补充要求

本包的 PNG 覆盖：主界面、Chrome 上下文、设置弹层。交互 HTML 还可查看文字输入、手势说明、全部 App、全部快捷键和沉浸模式。

下列状态已给出实施规则，但不是已完成的独立视觉稿：断连 / 重连、权限拒绝、应用不存在、Touch Bar 不支持、转写失败和发送失败。开发接入时在当前信息区保留状态文字与恢复入口；不要无声失败，也不要仍显示「已连接」。这些真实异常流程需与现有 App 业务一起验收。

## 8. 验收要点

- 与同编号 PNG 对照颜色、层次、圆角和区域位置；不要混合 02、05。
- 核心触控区域连续，避免透明装饰层截获触摸。
- 02 左侧触控、右侧快捷键、底部 App；05 左右侧控制、中央触控。
- 按下态、当前 App、录音态与不可用态可以区分。
- 触控手势和快捷键动作不因为主题选择而改变。
- 不使用原型里的固定设备值、模拟成功或固定转写作为真实状态。
- 在目标 Android Pad 上验收横屏、安全边距、字体缩放、触控面积、取消和失焦；本包浏览器检查不替代真机检查。
